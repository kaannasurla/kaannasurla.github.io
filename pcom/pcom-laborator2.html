02

Biții vin pe fir. Cadrele unde sunt?

Aplicațiile lucrează cu mesaje, structuri, fișiere întregi. Nivelul fizic (lab 1) transmite doar un flux de biți. La nivelul legătură de date, unitatea de informație este cadrul (frame): secvența de biți care formează un bloc logic de date. Receptorul trebuie să găsească singur granițele dintre cadre.

Mai jos, în flux sunt ascunse caracterele 'A' și 'B'. Mută locul de unde receptorul începe să numere câte 8 biți.

Problema centrală: cum codifică emițătorul cadrele astfel încât receptorul să le poată extrage eficient din fluxul de biți? Varianta naivă „fiecare 8 biți sunt un octet” nu merge: nivelul fizic nu e perfect, iar o singură pierdere de sincronizare strică tot ce urmează.

03

Bit stuffing

Cadrul se delimitează cu un flag: 01111110. Receptorul începe să citească abia după ce vede flag-ul. Ca flag-ul să nu poată apărea niciodată în date, emițătorul aplică o regulă: după cinci de 1 consecutivi, inserează un 0. Receptorul face invers: după cinci de 1, scoate 0-ul.

flag 01111110 0 inserat de emițător / scos de receptor
emițător111111 → 1111101
receptor1111101 → 111111
receptor1111100 → 111110 (doar primul 0 după cei cinci de 1 dispare)

Specificația, ca într-un RFC: un cadru = delimitator, payload, delimitator. Delimitatorul e 01111110. În payload, după orice secvență de cinci biți de 1 se inserează un 0, ca delimitatorul să nu apară niciodată în datele transmise. Așa face și HDLC.

04

Byte (character) stuffing

Dacă nivelul fizic ne dă un serviciu de trimis octeți, aceeași idee merge cu caractere de control ASCII: DLE (Data Link Escape, 0x10), STX (Start of Text, 0x02), ETX (End of Text, 0x03). Cadrul începe cu DLE STX și se termină cu DLE ETX. Un DLE din date se trimite dublat.

05

Byte stuffing în C

Placa de rețea (NIC) are în firmware două funcții: send_byte trimite un octet, recv_byte întoarce un octet. Atenție: când nu trimite nimeni nimic, recv_byte întoarce date oarecare, deci receptorul trebuie să sară peste gunoi până găsește DLE STX. De obicei, protocolul se scrie ca o bibliotecă folosită și de emițător, și de receptor.

emițător
#define DLE 0x10
#define STX 0x02
#define ETX 0x03

/* presupunem: void send_byte(char c);
               char recv_byte(void);   */

void send_frame(const char *buf, int size)
{
    send_byte(DLE);
    send_byte(STX);

    for (int i = 0; i < size; i++) {
        if (buf[i] == DLE)
            send_byte(DLE);    /* escape: DLE devine DLE DLE */
        send_byte(buf[i]);
    }

    send_byte(DLE);
    send_byte(ETX);
}
receptor
/* întoarce lungimea cadrului sau -1 */
int recv_frame(char *buf, int max_size)
{
    char c1 = recv_byte();
    char c2 = recv_byte();

    /* sărim peste gunoi până la DLE STX */
    while (c1 != DLE || c2 != STX) {
        c1 = c2;
        c2 = recv_byte();
    }

    int i = 0;
    while (1) {
        char c = recv_byte();
        if (c == DLE) {
            c = recv_byte();
            if (c == ETX)
                return i;      /* DLE ETX: gata */
            if (c != DLE)
                return -1;     /* cadru stricat */
            /* DLE DLE: un singur DLE în date */
        }
        if (i == max_size)
            return -1;         /* nu mai e loc */
        buf[i++] = c;
    }
}

Față de varianta din laborator, am scris condiția din while pe o singură linie, cu || (receptorul caută până când nu mai e adevărat că „c1 nu e DLE sau c2 nu e STX”). Am pus și un return pentru cazul în care cadrul nu încape în buffer. Pe tabla următoare vezi exact pașii prin care trece receptorul.

Unul sau mai mulți receptori?

Câți receptori are un cadru depinde de mediu. Point-to-point: exact două dispozitive, deci nu trebuie să spui cui îi trimiți. Protocoale de nivel 2 făcute pentru asta: PPP și HDLC. Pe harta ARPANET din decembrie 1970, legătura STANFORD–UTAH era point-to-point. Point-to-multipoint: un emițător, mai mulți receptori pe același mediu. Cel mai des, destinația se pune într-un câmp din antet, cum e adresa MAC la Ethernet.

09

Ce se folosește de fapt: Ethernet

Ethernet e un protocol foarte răspândit la nivelul de acces la rețea. A fost dezvoltat la Xerox PARC în 1973–1974, ca să comunice între ele calculatoarele Alto, pornind de la ALOHAnet, pe care Robert Metcalfe îl studiase în doctorat (primul nume: Alto Aloha Network). Antetul real e mai complicat decât ce implementăm noi. Cadrul e delimitat de un preambul la început și de o pauză (Interpacket Gap) la final. Apasă pe un câmp.

InfiniBand: simboluri speciale

InfiniBand e alternativa la Ethernet din datacentere. A apărut în 1999 din unirea a două proiecte rivale, Future I/O (Compaq, IBM, HP) și NGIO (condus de Intel), pentru că magistrala PCI devenise o limită. Versiunea 1.0 a specificației a apărut în 2000. Pentru framing folosește două simboluri: SLP (Start of Link Packet, codat K28.2) și EGP (End of Good Packet, codat K29.7). Simbolurile K din codarea 8b/10b nu corespund niciunui octet de date, deci nu pot apărea în payload și nu e nevoie de stuffing.

Cadrul ca struct în C

În schelet, ./run_experiment.sh pornește simulatorul nivelului fizic și rulează ./recv și ./send. Mediul e ideal: fără pierderi, fără erori. Cadrul îl descriem ca struct, cu __attribute__((packed)), ca să nu adauge compilatorul octeți de aliniere.

exercițiul 1 · point-to-point
struct __attribute__((packed)) Frame {
    char frame_delim_start[2]; /* DLE STX */
    char payload[30];          /* mereu 30 */
    char frame_delim_end[2];   /* DLE ETX */
};
exercițiul 2 · point-to-multipoint
struct __attribute__((packed)) Frame {
    char frame_delim_start[2]; /* DLE STX */
    int  source;               /* cine trimite */
    int  dest;                 /* cui */
    char payload[30];
    char frame_delim_end[2];   /* DLE ETX */
};

Iată cum arată în memorie structura de la exercițiul 2. Schimbă valorile și comută între packed și alinierea normală.

trimiterea: delimitatorii ca atare, tot ce e între ei prin escape

f.source = 1;

Capcane

✗ escape doar pe text, nu și pe int-uri

source = 16 înseamnă, în memorie, octeții 10 00 00 00. Primul octet e exact DLE. Dacă dublezi DLE-urile doar în payload, receptorul vede DLE 00 și declară cadrul stricat. Escape-ul se aplică la tot ce e între delimitatori (vezi tabla 10).

✗ DEL în loc de DLE

În comentariile din enunț apare „DEL STX”. E vorba de DLE (0x10). DEL (0x7F) e alt caracter.

✗ primul octet primit e DLE?

Nu neapărat: recv_byte întoarce gunoi când nu trimite nimeni. Caută DLE STX, nu presupune că ești deja la începutul cadrului.

✗ fără packed

Compilatorul pune 2 octeți de aliniere înainte de source: sizeof devine 44 în loc de 42, iar cele două capete nu mai sunt de acord asupra formatului.

✗ scrii peste max_size

Un cadru stricat sau gunoiul de pe fir pot părea un cadru foarte lung. Verifică spațiul înainte de buf[i++] = c.

✗ două mașini diferite

Un int poate avea alt ordin al octeților pe cealaltă mașină. Trimite-l cu htonl, citește-l cu ntohl.

✗ latența, cu două ceasuri

„Ora de acum minus ora din cadru” are sens doar dacă cele două ceasuri sunt sincronizate. Pe mașini diferite, măsoară dus-întors și împarte la 2.

02

Ce este un protocol?

Un protocol e un set de reguli bine definite, pe care ambele părți le respectă cât timp comunică. Și oamenii folosesc protocoale, doar că nu le scriu nicăieri.

sintaxăcum arată fiecare mesaj (format, câmpuri, ordinea lor)
semanticăce înseamnă fiecare mesaj și ce trebuie să faci când îl primești
ordinecine vorbește primul, cine răspunde, ce faci când ceva se pierde
03

Nivelul fizic

Protocoalele și tehnicile prin care informația trece efectiv printr-un mediu de transmisie (legătura, „link”-ul). Bitul trebuie pus pe ceva care se poate măsura la celălalt capăt.

04

Biți pe fir

Emițătorul pune 5 V pentru un 1 și 0 V pentru un 0, câte un bit la fiecare T ms. Receptorul măsoară tensiunea tot la fiecare T ms (punctele). Scrie ceva și uită-te ce trece prin cablu.

rata de biți = biți / secundă

De ce contează ceasul? Dacă emițătorul și receptorul nu numără timpul la fel, receptorul măsoară în locuri greșite și citește alți biți. De asta protocoalele reale trimit și informație de sincronizare: Ethernet, de exemplu, pune în fața fiecărui cadru un preambul de biți alternanți.

05

Internetul, pe scurt

La început, la sfârșitul anilor ’60 și începutul anilor ’70, Internetul nu era mult mai mult decât câteva calculatoare legate prin cabluri, cu un protocol simplu. În câțiva ani a devenit mult mai complicat.

OSI vs. TCP/IP

Ca să poată fi gândit pe bucăți, Internetul e împărțit în niveluri. Modelul OSI e cel mai cunoscut (7 niveluri), dar în practică se folosește TCP/IP (4). Apasă pe un nivel.

Un server în o linie

telnet e un client. Cu netcat pornim un server care ascultă pe portul 9090, apoi ne conectăm la el din alt terminal. Încearcă: conectează clientul, apoi scrie în oricare fereastră și apasă Enter.

terminal 1 · server
terminal 2 · client

Portul clientului (de ex. 53500) nu l-a ales nimeni de mână: îl dă sistemul de operare la fiecare conexiune, dintr-un interval de porturi efemere. Textul exact afișat de netcat diferă puțin de la o variantă la alta. Concluzia: funcționalitatea de rețea poate fi implementată de procese obișnuite, iar două procese de pe aceeași mașină pot vorbi prin rețea.

File descriptors

Un file descriptor e un număr întreg care identifică un fișier deschis în tabela procesului. Fiecare proces are propria tabelă și pornește cu 0, 1, 2 deja ocupate. Detaliul important pentru PCom: și un socket e tot un file descriptor. Încearcă butoanele; apasă pe un rând ca să-l selectezi pentru close.

Regula: open și socket întorc mereu cel mai mic număr liber. Închide 1, apoi deschide un fișier: tot ce afișezi cu printf ajunge în fișier.

Copierea unui fișier, cu apeluri de sistem

copy.c
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

#define BUFLEN 1024

static void fatal(const char *msg)
{
    perror(msg);
    exit(EXIT_FAILURE);
}

int main(int argc, char *argv[])
{
    if (argc != 3) {
        fprintf(stderr, "Utilizare: %s sursa destinatie\n", argv[0]);
        return EXIT_FAILURE;
    }

    int src = open(argv[1], O_RDONLY);
    if (src < 0)
        fatal("open sursa");

    int dst = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (dst < 0)
        fatal("open destinatie");

    char buf[BUFLEN];
    ssize_t n;
    while ((n = read(src, buf, sizeof(buf))) > 0) {   /* 0 = sfârșit de fișier */
        if (write(dst, buf, n) < 0)
            fatal("write");
    }
    if (n < 0)
        fatal("read");

    close(src);
    close(dst);
    return 0;
}

read mută singur cursorul din fișier: fiecare apel continuă de unde a rămas cel dinainte. Cu lseek poți muta cursorul unde vrei.

Verifică valoarea întoarsă de fiecare apel și afișează un mesaj de eroare care chiar spune ceva. > 0 înseamnă câți octeți s-au citit, 0 înseamnă sfârșit de fișier, -1 înseamnă eroare (detaliile sunt în errno, le afișează perror).

Primul socket: UDP

Pentru exercițiul 3 pornim de la laboratorul de IPC de la SO: udp_socket.c e un singur fișier care, fără argumente, e receptor, iar cu -s e emițător. Comunică prin 127.0.0.1:5000.

apelurile esențiale
/* ambele părți */
int fd = socket(AF_INET, SOCK_DGRAM, 0); /* un fd */
struct sockaddr_in addr = {0};
addr.sin_family = AF_INET;
addr.sin_port = htons(5000);  /* big-endian */
addr.sin_addr.s_addr = inet_addr("127.0.0.1");

/* receptor */
bind(fd, (struct sockaddr *)&addr, sizeof(addr));
char buf[BUFSIZ];
ssize_t n = recvfrom(fd, buf, sizeof(buf) - 1,
                     0, NULL, NULL);
if (n >= 0)
    buf[n] = '\0';
printf("%s\n", buf);

/* emițător */
sendto(fd, "Hello World", 11, 0,
       (struct sockaddr *)&addr, sizeof(addr));

captura, pe loopback

Capcane

✗ read / write nu promit tot ce ai cerut

read(fd, buf, 1024) poate întoarce mai puțin de 1024 chiar dacă mai sunt date. Pe socket-uri se întâmplă des. La write e la fel: poate scrie doar o parte.

greșit
read(fd, buf, sizeof(buf));        /* o singură dată */
write(1, buf, sizeof(buf));        /* scrie și gunoi */
corect
ssize_t write_all(int fd, const char *buf, size_t len)
{
    size_t done = 0;
    while (done < len) {
        ssize_t w = write(fd, buf + done, len - done);
        if (w < 0)
            return -1;
        done += w;
    }
    return done;
}

✗ filtrezi 127.0.0.1 pe Wi-Fi

Pachetele către localhost nu ajung niciodată pe placa de rețea, ci rămân pe lo. Capturează pe lo sau any.

✗ ip.addr nu prinde nimic

Poate traficul merge pe IPv6. De aceea telnet -4 forțează IPv4; altfel încearcă ipv6.addr.

✗ serverul HTTP „nu răspunde”

Ai uitat linia goală de la final. Sau ai scris prea încet și serverul a închis conexiunea: copiază cererea, nu o tasta.

✗ host 8.8.8.8 în Wireshark

Asta e sintaxă de tcpdump. Bara devine roșie; în Wireshark scrii ip.addr == 8.8.8.8 (tabla 11).

✗ nicio interfață în Wireshark

Nu ai drepturi de captură. Intră în grupul wireshark și deschide un shell nou, sau pornește cu sudo.

✗ nu verifici ce întoarce

open, socket, bind, sendto… toate pot eșua. Fără verificare, eroarea iese la iveală trei funcții mai târziu.
